# MiniMax-H3 硬性限制

寫 prompt 前先確認要用的數字都在這張表上。這些是模型層級的限制，prompt 寫得再好也繞不過去。

## 時長：frame grid

合法 frame 數必須是 `17n + 5`，24 fps。請求的秒數會被吸附到最近的合法格子。

| n | frames | 秒數 | 備註 |
|---|---|---|---|
| 7 | 124 | 5.167 | 最短實用長度 |
| 13 | 226 | 9.417 | |
| 14 | 243 | 10.125 | |
| 20 | 345 | 14.375 | 社群 768p 推論 benchmark 用的長度 |
| 21 | **362** | **15.083** | 上限，本專案預設 |

ComfyUI 換算式（放在 `ComfyMathExpression`，`a` = 秒數）：

```
max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17
```

陷阱：`a = 14.4` 會算出 362 而不是 345。要 345 必須填精確的 `14.375`。

一個 30 秒場景 = 2 × 362 frames = 30.167 秒。13 個場景 = 26 段 = 392.2 秒。

## 參考檔案數量

Ref2VA 單次請求：

| 類型 | 上限 |
|---|---|
| 圖片 | 9 |
| 影片 | 3（每段 2–15 秒）|
| 音訊 | 3 |
| 合計 | 12 |

音訊不能單獨存在，必須至少搭配一張圖或一支影片。

實務建議：**一段 4 張圖以內**。超過之後身份鎖定明顯變鬆，這比理論上限重要得多。

## Prompt 長度

7000 字元。六區段的完整分段 prompt 通常落在 2500–4000，不太會撞到。

## 比例

- Base 模式（T2VA / I2VA / FL2VA / L2VA）：adaptive, 21:9, 16:9, 4:3, 1:1, 3:4, 9:16
- **Ref2VA 只支援 16:9 和 9:16**

本專案用 16:9。

## 模式與互斥

| 模式 | 輸入 | 用途 |
|---|---|---|
| T2VA | 純文字 | 無參考的空景、轉場 |
| I2VA | 首幀 + 文字 | 鏈式接續的後段 |
| FL2VA | 首幀 + 尾幀 + 文字 | 指定起訖構圖 |
| L2VA | 尾幀 + 文字 | 收束到指定畫面 |
| Ref2VA | 參考圖／影片／音訊 + 文字 | 身份鎖定，本專案主力 |

**Ref2VA 的參考輸入和 first-frame / last-frame 互斥，不能在同一次呼叫同時給。**
這是「跨段一致性」那節要處理的根本原因。

Ref2VA 需要 `ref2va` checkpoint，和 T2VA/FL2VA 用的 `fl2va` 是不同的權重檔，
ComfyUI 裡的載入節點也不同。切模式時記得換。

## 標籤語義

官方標籤表：

| 標籤 | 含義 |
|---|---|
| `<Subject N>` | 從參考抽取的可重用可見內容（人物、場景、服裝、風格、動作）|
| `<Picture N>` | 作為 frame anchor / keyframe / 構圖錨點的參考圖 |
| `<Video N>` | 作為剪輯來源／延續／時間結構來源的參考影片 |
| `<Audio N>` | 被複製或參照的音訊訊號 |

同一個標籤在整段 prompt 內語義固定不變。

按這張表，鎖角色身份應該用 `<Subject N>`。既有的 seg04 用的是 `<Picture N>`。
兩者都有人用且都能出圖，差別在身份保持強度，需要實測。見 SKILL.md 的「待驗證的兩個決定」。

## 本機部署的額外限制

- 開源權重只有 H3-Base，**768p 上限**。負責升到 2K 的 H3-Regenerate-2K 模組沒有開源。
- 官方線上服務前面掛的 prompt 改寫模組 **H3-Context-IR 也沒有開源**。
  本機跑等於直接把 prompt 餵進模型，所以 prompt 必須**自己寫成完整的六區段結構**，
  這正是這個 skill 存在的理由。
